# 架构说明

> 这篇讲「为什么这样分层、一次运行里数据怎么流、哪几条不变量不能破」。
> 具体操作看 `接新客户一页清单.md`，配置键看 `配置参考.md`，判定看 `判定规则.md`。

---

## 1. 这套东西的形状

一句话：**一份代码 + 多个客户项目**，靠「复制分发」而不是「import 引用」来复用。

```
                     ┌──────────────────────────────────────┐
                     │  _公共/           唯一真本（25 个文件） │
                     └───────────────┬──────────────────────┘
                                     │ 同步.py --apply（复制 + 版本戳）
             ┌───────────────────────┼───────────────────────┐
             ▼                       ▼                       ▼
     05 客户A/数据监控        05 客户B/数据监控        05 客户C/数据监控
     （完整副本 + 自己的 ini + 自己的 数据/ 与 看板）
```

每个客户项目都是一份**完整可运行**的副本，不依赖 `_公共/` 在运行时存在。代价是改代码要重新分发，收益是单个项目搬走/备份/移交都不缺东西 —— 客户目录整棵拷给别人就能跑。

## 2. 三层

```
┌─ 平台适配层  平台/<site>/<product>/          4 个脚本
│    平台取数.py     怎么从平台拿数 → 日汇总.csv
│    库内导出.py     MySQL 直连 → 两份库内 CSV + 入库时间.csv
│    凭证刷新.py     从浏览器 CDP 读 cookie → curl_*.txt
│    账户取数.py     （可选，目前无调用方）
│
├─ 业务层     业务/*.py  →  分发后平铺在项目根
│    项目配置.py     唯一读配置的入口（含校验）
│    每日对账.py     5 个阶段串起来，产出结论 + 写表
│    自动对账.py     任务计划入口：时段护栏 → 起浏览器 → 跑对账 → 推送
│    写入日监控.py   重建 Excel 看板
│    排查.py         只读诊断（某一天为什么对不上）
│    凭证体检.py     每日探活，积累 TTL 样本
│
└─ 监控内核  监控内核/                        14 个模块
     判定.py  契约.py  路径.py  基础.py  数据.py  日志.py
     子流程.py  通知.py  登录态.py  消息.py  自检.py  版本.py
     自测_判定.py  __init__.py
```

**依赖方向是单向的**：业务层 → 内核层 → `路径.py`（唯一叶子）。`判定.py` 不 import 任何东西，连标准库都不用，所以它可以被单独测试、被任何一层调用。

**业务层不 import 平台层**。它只 import `路径.py` 里的三个路径常量（`SCRIPT_REFRESH` / `SCRIPT_FETCH` / `SCRIPT_EXPORT`），运行时用 `基础.load_module()` 按绝对路径加载。这是「换平台不用改业务层」的唯一原因 —— 也是为什么适配层只需要遵守「文件名 + 函数名」的约定（见 `换平台改造清单.md`）。

## 3. 一次运行的数据流

```
计划任务 15:30
   └─ 自动对账.py
        ├─ 读 通知配置.ini；Tee 接管 stdout（pythonw 下没有控制台）
        ├─ [运行时段] 护栏：不在窗口内 → 不取数、不推送、退 0
        ├─ 起浏览器（每个凭证分组一个 CDP 端口）
        ├─ 子进程跑 每日对账.py  ← 进程边界，拿退出码 + 全部输出文本
        │     ├─ [1/5] 凭证刷新  → 数据/平台数据/curl_*.txt、凭证状态.csv
        │     ├─ [2/5] 平台取数  → 数据/平台数据/日汇总.csv    → 契约.check_platform
        │     ├─ [3/5] 库内导出  → 标准投/简单投 CSV + 入库时间.csv
        │     │                     → 契约.check_std / check_sim / check_ingest / check_shops
        │     ├─ [4/5] 判定       → 每店×每日 → 8 态结论
        │     └─ [5/5] 写入日监控 → 01_日数据监控.xlsx（+ 备份）
        ├─ 消息.parse_output  ← 用正则从上面那段 stdout 里抽结论
        ├─ 登录态.check_sso   ← 读 凭证状态.csv，快过期就单独推一条
        └─ 通知.notify        ← 企微群机器人；失败退小助手
```

关键点：**只有 `自动对账.py` 会发消息**。`每日对账.py` 全程只打印，它的输出是给父进程「正则解析」用的 —— 所以改 `每日对账.py` 的打印格式会静默打断通知（见 `判定规则.md` 的 `PASS` 别名一节）。

## 4. 分发模型：版本戳与三态

`_公共/` 是唯一真本。每个客户项目里有一个 `版本戳.json`，记着「上次分发时每个文件的 md5」。`同步.py` 逐文件比三种情况：

| 情况 | 判定 | 动作 |
|---|---|---|
| 目标 == 源 | 一致 | 什么都不做 |
| 目标 != 源，但 == 版本戳里的 md5 | 源更新了 | 覆盖写入 |
| 目标 != 源，且 != 版本戳里的 md5 | 本地被手改过 | **报冲突，不覆盖** |

第三态是这套机制存在的理由：少了它，任何一次分发都会静默吃掉别人手改的副本。

项目每次开跑时会核对一次版本（`监控内核/版本.py`），但**只提示不拦流程** —— 所以「分发落后」不会让任务失败，只会多一行提示。

## 5. 内核 14 个模块的职责

| 模块 | 一句话 |
|---|---|
| `路径.py` | 全项目唯一的路径定义处；`BASE` 由文件位置上跳两级推出 |
| `判定.py` | 8 态判定的唯一实现，纯函数；同时是状态文案的唯一来源 |
| `契约.py` | 适配层产出 CSV 的形状自检（列名 / 日期 / 金额 / 店铺名） |
| `基础.py` | 日期解析、按路径装载中文名模块、控制台排版、开跑自检、运行时段 |
| `数据.py` | 从 CSV 派生的信号：入库时刻表、账户数中位数基准 |
| `日志.py` | pythonw 下接管 stdout（Tee）、按时分建日志、90 天清理 |
| `子流程.py` | 子进程跑脚本并落日志、只关自己起的浏览器 |
| `通知.py` | 企微群机器人优先，失败退小助手；强制绕过 HTTP_PROXY |
| `登录态.py` | sso 到期提醒 + 按「本轮到期时刻」去重 |
| `消息.py` | 从子流程输出抽结论、拼推送文案、定义退出码文案表 |
| `自检.py` | AST 扫业务代码里有没有残留上一家客户的名字（只扫字符串常量） |
| `版本.py` | 分发副本核对：版本号 + 每个文件 md5 |
| `自测_判定.py` | 判定的回归自测（75 项断言，含真实事故案例） |
| `__init__.py` | 包门面，预导入 9 个子模块 |

## 6. 不能破的不变量

1. **路径只在 `路径.py` 定义**。任何脚本自己拼 `BASE + "数据" + ...` 都是债 —— 换项目时漏改一处，就会出现「主流程读 A、看板读 B」的静默错位。
2. **判定只有一份实现**。业务层不许自己算 `abs(diff) <= tol` 然后打「报警」。历史上有过两份实现，导致日志判「不报警」、看板判「报警」，而人只看 Excel。
3. **适配层产出必须先过契约**。取数刚写完的 CSV 立刻验形状，缺列 / 日期格式错 / 金额带千分位都在这里停住 —— 否则会一路跑完，在「全部 0 元、全部 PASS」处静默收场。
4. **公共代码不在副本里改**。改了就是第三态冲突，两边从此分叉，而且每天照跑、没人发现。
5. **发消息只在 `自动对账.py`**。其它脚本打印即可，别自己推送。

## 7. 目录约定（改名前先想清楚）

```
数据/
├── 平台数据/            日汇总.csv、凭证状态.csv、凭证体检.csv、curl_*.txt
├── 库内数据/            入库时间.csv、连接配置.ini
├── 标准投库内数据/各子店铺每月每日数据/各子店铺每月每日数据.csv
└── 简单投库内数据/各子店铺每月每日数据/各子店铺每月每日数据.csv

_browser/A|B/            两个浏览器 profile（每个分组一个，绝不共用）
logs/                    按月日时分的运行日志
产出/                    临时产物
01_日数据监控.xlsx        看板；01_日数据监控_备份.xlsx 是上一版
```

目录名是中文，**不要为了「兼容」改成拼音** —— 已有数据目录、契约、看板全部按这些名字找，改了就对不上，而且不会报错。

## 8. 已知的结构性限制

- 一个项目只能挂一个平台（`路径.py` 的 `PLATFORM/PRODUCT` 是模块级单值）。
- 口径固定为「平台 − 标准投 − 简单投」三列一组（见 `README.md` 的支持范围）。
- 只支持 Windows：注册表找 Chrome/Edge、`netstat`/`taskkill`、`bat` 是 GBK + CRLF。

这些限制的解除方式写在 `换平台改造清单.md` 和 `README.md` 里，不要在客户项目里绕。
