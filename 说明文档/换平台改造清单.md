# 换平台改造清单

> 适用对象：**换掉整个平台适配层**（例如从「小红书 聚光」换成「巨量引擎」）。
> 同平台加客户不用看这份，走 `接新客户一页清单.md`。
>
> 公共代码版本：2026-11-24　｜　状态：这份清单是**待办账单**，不是「已支持」

---

## 0. 先分清两件事

| 需求 | 现在能做吗 | 做法 |
|---|---|---|
| 一个客户换到另一个平台 | 要改代码，按本清单逐项过 | 见下面 §2 |
| 一个客户**同时**看两个平台 | **不支持** | `路径.py` 的 `PLATFORM/PRODUCT` 是模块级单值，一个项目只能挂一个平台。要并存得先改目录结构与常量，属于结构性改造 |
| 同平台再加一个客户 | 支持，一条命令 | `python 新建客户.py "05 客户名" --port 9242,9243` |

**为什么当初没做多平台**：这套代码的前提是「一份代码 + 多个客户」，不是「一份代码 + 多个平台」。多平台会让 `契约.py` 的列名、`判定.py` 的对比维度、看板的列组同时变成二维，改一次要动内核，风险远大于收益。真要并存，建议**开第二个仓库**，别在这个仓库里加分支。

---

## 1. 适配层的契约（脚本名 + 函数名，都是隐式的）

`路径.py` 按 `平台/<site>/<product>/` 拼路径，`基础.load_module()` 按**绝对路径**加载。
业务层不 import 平台包，所以这层契约没有类型检查，**写错函数名只会报 `AttributeError`**。

必须具备四个文件，文件名固定：

```
平台/<site>/<product>/
├── 凭证刷新.py   run(check_only=False) -> int          可用份数
├── 平台取数.py   main() -> 0|1                          0 全成功 / 1 有店失败
├── 库内导出.py   load_cfg() -> (cfg, tables)
│                 has_simple(tables) -> bool
│                 do_export(unit, cfg, tables, dry_run) -> bool
│                 export_ingest(cfg, tables, days=60) -> bool
└── 账户取数.py   main(argv) -> 0|1|2|3                  （目前无调用方，可选）
```

外加 `平台/<site>/配置/<product>.ini`，字段清单见 `项目配置.py` 的 `_sec(...)` 调用处。

## 2. 必须改的地方（按硬度排序）

### 2.1 硬阻塞 —— 不改就跑不起来

| # | 位置 | 写死了什么 | 改法 |
|---|---|---|---|
| 1 | `_公共/业务/自动对账.py` 的 `NEED_FILES` | `平台/<平台>/配置/聚光.ini` | 改成按 `[平台] product` 拼 |
| 2 | `_公共/业务/项目配置.py` `[凭证字段]` + `[凭证A..]` | 强制 cookie 后缀 / `login_proof` / 浏览器 port+profile+curl 四件套 | 把「平台需要哪些凭证字段」改成平台 ini 自己声明；API Key 类平台没有 cookie 也没有浏览器实例 |
| 3 | `_公共/监控内核/契约.py` 的平台表 SPEC | 列名 `fee_yuan / statistics_date / shop_name / fetched_at` | 列名由平台声明（或映射层先归一化再进契约） |
| 4 | `_公共/平台/小红书/聚光/凭证刷新.py` | `mcc.xiaohongshu.com` 主机常量、sso 7 天假设 | 新适配层自己重写；别照抄这个文件 |
| 5 | `_公共/平台/小红书/聚光/凭证体检.py` | `PROBE` 探测地址 | 同上（注意它在 `业务/` 下，位置就不对） |

### 2.2 半阻塞 —— 「两路库内」的模型

现在的数据模型是：**平台数 − 标准投 − 简单投 = 差额**，每店固定 4 列、两条库内路线。

| 位置 | 内容 |
|---|---|
| `_公共/业务/每日对账.py` | `标准投 + 简单投` 两路导出与求和 |
| `_公共/监控内核/契约.py` | 固定 4 个校验任务，只有简单投是 optional |
| `_公共/监控内核/路径.py` | `STD_CSV` / `SIM_CSV` 两条写死路径 |
| `_公共/业务/写入日监控.py` | 每个店铺固定 4 列（平台/标准投/简单投/差额） |

平台只有一路金额时：把 `[tables] simple` 留空即可（三处会明确跳过），**不用改代码**。
平台有第三路（例如「品牌广告」）时：必须改上面四处，属于第 1 阶段改造。

### 2.3 不影响运行，但会误导人

`排查.py` 的文案、`每日对账.py` 报错里的 `平台/<平台>/聚光/`、`启动取数浏览器.py` 的注释，都写着小红书/聚光的措辞。换平台时顺手改掉，否则排查时会对着错的路径找。

## 3. 验收（缺一不可）

```bash
python 项目配置.py                  # 全部检查通过
python -m 监控内核.契约 --selftest  # 6 项
python 写入日监控.py --selftest      # 表结构不被写串
python -m 监控内核.自测_判定         # 75 项
python 凭证刷新.py                   # N/N 份可用
python 每日对账.py --no-write        # 有结论（0/3/4 都算跑通）
```

新平台的店铺数、组织码、凭证分组全部走 ini，**不要**为了跑通临时改公共代码 —— 那会让下一个客户继承你的临时改动。

## 4. 已知缺口

- `新建客户.py` 只生成「小红书/聚光」一套（`PLATFORM_DIR` / `PRODUCT` 写死）。换平台要手工建目录，或先改那个脚本。
- 适配层的四个函数名没有断言，写错只报 `AttributeError`。第 1 阶段的「平台适配接口自检」是为了补这个洞。
- `账户取数.py` 和 `凭证体检.py` 目前**不在任何调用链里**，却含有最硬的平台常量 —— 换平台时别以为它们会被自动带着换。
