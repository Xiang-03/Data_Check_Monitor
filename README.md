# 数据监控骨架

一套「一份代码 + 多个客户项目」的日对账骨架。适合的场景：

- 同一个平台（目前是小红书聚光）下有**多个客户**，每个客户有自己的店铺、子账号、数据库；
- 每天定时抓平台数据 + 从库内导出明细，逐日比对差额，超容差就告警，同时生成监控表；
- 客户会越来越多，**不希望每接一个就复制一遍代码**。

## 它解决什么

这类系统最危险的失效方式不是崩溃，而是**不报错但结果错**：漏了一个子账号、店名少一个空格、
标题顶着上一家的名字发出去。所以这套骨架的重点不是「自动化」，而是**三套护栏**：

| 护栏 | 作用 |
|---|---|
| `监控内核/判定.py` | 判定逻辑只有一份，8 状态机，可被穷举验证（75 项等价类断言） |
| `监控内核/契约.py` | 产出 CSV 的形状、日期、金额、店铺名逐项校验，不符直接退出码 6 |
| `监控内核/自检.py` | 扫业务代码里有没有残留别家的字面量（只扫 AST 字符串常量，跳过注释） |
| `监控内核/版本.py` + `同步.py` | 公共代码分发 + 版本戳，副本被手改会在下次同步时报冲突 |

## 支持范围（接手前先看这一段）

这套骨架目前只覆盖**一种形状**，不是通用对账框架：

| 维度 | 现在支持 | 不支持 |
|---|---|---|
| 平台 | 只有「小红书 聚光」一套适配层 | 第二平台要改代码，见 [`说明文档/换平台改造清单.md`](<说明文档/换平台改造清单.md>) |
| 口径 | **平台消耗 − 标准投 − 简单投 = 差额**；简单投可以没有（`[tables] simple` 留空） | 第三路金额、非扣减式勾稽 |
| 店铺数 | 任意（看板列组按 `[店铺] list` 生成） | 一个项目挂两个平台 |

要加第二种形状（第二平台 / 第三路金额）：**先改 `_公共/`，再 `同步.py --apply` 分发**。

> 不要在自己项目的副本里改公共代码。副本一改，`同步.py` 会一直报「冲突」不覆盖，
> 版本核对又只提示不拦流程 —— 两边从此各跑各的，而且每天照跑，没人会发现。

## 结构

```
_公共/                 ← 唯一真本（25 个文件）
├── 监控内核/          14 个模块：判定/契约/路径/基础/数据/日志/子流程/通知/登录态/消息/自检/版本/自测/__init__
├── 业务/             每日对账 / 自动对账 / 写入日监控 / 排查 / 凭证体检 / 项目配置
├── 平台/<站点>/<产品>/  平台适配层：平台取数 / 库内导出 / 凭证刷新 / 账户取数
├── 运行/             启动取数浏览器（起带调试端口的专用浏览器）
├── 同步.py           分发 / 预览 / 三态冲突检测
├── 目标.json         分发目标（新客户由 新建客户.py 自动登记）
└── 版本.txt          版本号

模板/                  ← 新客户的配置骨架（4 个 ini + 3 个 bat，bat 是 CRLF+GBK）
说明文档/              ← 换平台改造清单（换平台要改哪几处；同平台加客户不看）
新建客户.py             ← 一条命令生成可运行的项目骨架
自检_骨架.py            ← 克隆后先跑这个（依赖 / 判定 / 契约 / 临时建项目验表结构）
迁移自检.py             ← 已有项目的只读体检：配置 / 表结构 / 契约 / 判定 / 自检 / 分发
心跳检查.py             ← 「今天到底跑没跑」：日志 / 退出码 / 取数新鲜度，异常推企业微信
接新客户一页清单.md      ← 接客户的逐步清单
requirements.txt        ← Python 依赖
```

## 快速开始

```bash
# 0) 首次：装依赖 + 验证这台机器能跑（必须全绿再往下）
python -m pip install -r requirements.txt
python 自检_骨架.py

# 1) 生成一个新客户项目（默认放在当前目录）
python 新建客户.py "05 客户名" --port 9242,9243

# 2) 按提示填 4 个 ini（脚本会列出还没填的占位符）
#    项目配置.ini / 平台/<站点>/配置/<产品>.ini / 数据/库内数据/连接配置.ini / 通知配置.ini

# 3) 起浏览器、登录、各导一份 curl，然后
python <项目目录>/数据监控/凭证刷新.py     # 期望 2/2
python <项目目录>/数据监控/每日对账.py --no-write
```

`自检_骨架.py` 不碰任何真实客户项目：它自己建一个临时项目、填假配置、验完就删。

## 环境要求

- **Windows**：浏览器 CDP 取 cookie、注册表里找 Chrome/Edge、`netstat`/`taskkill`、计划任务，
  `bat` 是 GBK + CRLF。macOS / Linux 跑不了这一层。
- Python 3.10+（实测 3.13）：`python -m pip install -r requirements.txt`
- Chrome + Edge 各一个专用 profile，首次人工登录一次（浏览器不会自动退出，登录态靠 profile 保留）
- 每个客户一个 MySQL 只读账号；平台侧需要一个能上小红书的本地代理（例如 `127.0.0.1:7897`）
- 通知：企业微信群机器人 webhook 必填；`wecom-cli` 小助手是本环境特有的可选兜底通道，
  没有它只是少一条兜底路径，不影响 webhook

## 不含什么

这个仓库**只有骨架**，不含任何客户项目、店铺数据、数据库凭据、通知 webhook。
这些都在每个客户自己的项目目录里，不进版本库。

## 使用范围

仅供团队内部使用与复制。仓库没有附开源许可，**不表示**可以对外分发：
要对外发布，先定许可（MIT / Apache-2.0 / 专有），再清理注释里的客户业务细节
（现有注释用 `客户A` / `子账号A` 匿名，但保留了账户数、金额量级等真实事故细节）。

## 设计取舍（写在代码注释里）

- **公共层是「复制分发」而不是「import 引用」**：`监控内核/路径.py` 靠文件位置推项目根，
  改成 sys.path 单源会让 `数据/`、`BROWSER_ROOT` 全部指错，且指错不报错（表现为「全部未登录」）。
  代价是每次改动要 `同步.py --apply` 分发。
- **客户特有的业务知识走配置**（`[提示]` / `[自检] forbid` / `[运行时段]`），不进代码。
- **冲突判定是三态**：`目标==源` 跳过 / `目标!=源 但 ==戳内` 覆盖 / `目标!=源 且 !=戳内` 冲突不覆盖。
  少了第三态，任何一次分发都会静默吃掉别人手改的副本。
