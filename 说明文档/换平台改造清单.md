# 换平台改造清单

> 适用对象：**换掉整个平台适配层**（例如从「小红书 聚光」换成「巨量引擎」）。
> 同平台加客户不用看这份，走 `接新客户一页清单.md`；配置键查 `配置参考.md`。
>
> 状态：这份是**改造账单**，不是「已支持」。按它改要动 `_公共/` 里的代码，不是改 ini。

---

## 1. 先分清三件事

| 需求 | 能不能做 | 做法 |
|---|---|---|
| 同平台再加一个客户 | **支持**，一条命令 | `python 新建客户.py "05 客户名" --port 9242,9243` |
| 一个客户换到另一个平台 | **要改代码** | 本文 §3~§6，动 9 处 + 写一套适配层 |
| 一个客户**同时**看两个平台 | **不支持** | `路径.py` 的 `PLATFORM/PRODUCT` 是模块级单值，一个项目只能挂一个平台 |

**为什么不做多平台并存**：这套代码的前提是「一份代码 + 多个客户」，不是「多个平台」。并存会让 `契约.py` 的列名、`判定.py` 的对比维度、看板的列组同时变成二维，改一次要动内核。真要并存，**开第二个仓库**，别在这个仓库里加分支。

---

## 2. 平台是怎么被找到的

没有 import，全是按路径拼出来的（这也是为什么函数名写错只会报 `AttributeError`）：

```
项目配置.ini
   [平台] site = 小红书
          product = 聚光
        │
        ▼
监控内核/路径.py:72-83
   PLATFORM, PRODUCT = plat_names()        ← 读 ini，缺了退回 小红书/聚光
   PLAT_DIR     = <项目>/平台/<site>
   PLAT_INI     = <项目>/平台/<site>/配置/<product>.ini
   ADAPTER_DIR  = <项目>/平台/<site>/<product>
   SCRIPT_REFRESH = ADAPTER_DIR/凭证刷新.py
   SCRIPT_FETCH   = ADAPTER_DIR/平台取数.py
   SCRIPT_EXPORT  = ADAPTER_DIR/库内导出.py
        │
        ▼
业务层（每日对账.py:215/226/259）
   基础.load_module(SCRIPT_FETCH).main()
        │
        ▼
监控内核/基础.py:84-98   用 importlib.util.spec_from_file_location 按绝对路径加载
```

所以换平台的完整动作是：**新建 `<site>/<product>` 目录 + 改 `[平台]` 两行**，业务层一行不用动。

## 3. 适配层契约

必须叫这四个名字，必须提供这些函数（没有类型检查，写错就是运行时报错）：

```
平台/<site>/<product>/
├── 凭证刷新.py   run(check_only=False) -> int
│                   返回可用的凭证份数（真值判）；每日对账拿它决定要不要继续
├── 平台取数.py   main() -> int
│                   0 = 全部成功；1 = 有店铺失败或全空（整天判不了）
├── 库内导出.py   load_cfg() -> (cfg: dict, tables: dict)
│                   has_simple(tables) -> bool            本项目有没有「简单投」这一路
│                   do_export(unit, cfg, tables, dry_run) -> bool
│                   export_ingest(cfg, tables, days=60) -> bool
└── 账户取数.py   main(argv) -> int                        （可选，目前无调用方）
```

### 3.1 产出 CSV 的列名是硬约束

`监控内核/契约.py` 会逐张校验，列名不同就直接失败（退出码 6）：

| 文件 | 必需列 | 说明 |
|---|---|---|
| `数据/平台数据/日汇总.csv` | `statistics_date, shop_name, fee_yuan, fetched_at` | 日期 `YYYY-MM-DD`；金额可转 float；不得 0 行；`fetched_at` 必须是**该日结束之后**取的时间 |
| `数据/标准投库内数据/各子店铺每月每日数据/各子店铺每月每日数据.csv` | `sub_account_id, statistics_date, shop_name, total_cost` | 账户数按 `sub_account_id` 去重统计 |
| `数据/简单投库内数据/…/各子店铺每月每日数据.csv` | 同上 | 本项目没有这一路 → 文件不产出即可 |
| `数据/库内数据/入库时间.csv` | `shop_name, statistics_date, last_created` | `last_created` 格式 `YYYY-MM-DD %H:%M:%S`，用来判断 RPA 是否还在写 |

金额单位：`fee_yuan` 与 `total_cost` 都是**元**。平台接口若返回分，在适配层里就除好，别让契约和判定看见分。

`source` 列可选，排查时会打印出来。

### 3.2 一个最小骨架长什么样

新平台没有现成的代码可抄，照下面这个形状填（**只是骨架，字段/接口按平台实际情况改**）：

```python
# 平台/<site>/<product>/平台取数.py
"""平台取数.py —— 从 <平台> 拉广告消耗，写 数据/平台数据/日汇总.csv"""
import csv
import os
import sys

from 监控内核.路径 import BASE, DATA_DIR, PLAT_CSV
import 项目配置 as CFG          # 拿 SHOPS / PLAT_SHOPS(店铺, 组织码, 分组)


def fetch_one(shop, org_code, group, day_range):
    """返回 [(日期, 金额元), ...]。这一步是平台特有的，其余都是通用管道。"""
    raise NotImplementedError


def main():
    rows = []
    for shop, org, grp in CFG.PLAT_SHOPS:
        for day, fee in fetch_one(shop, org, grp, CFG.LOOKBACK_DAYS):
            rows.append([day, shop, f"{fee:.2f}", now_str(), "api"])
    os.makedirs(DATA_DIR, exist_ok=True)
    with open(PLAT_CSV, "w", encoding="utf-8-sig", newline="") as f:
        w = csv.writer(f)
        w.writerow(["statistics_date", "shop_name", "fee_yuan", "fetched_at", "source"])
        w.writerows(rows)
    return 0 if rows else 1
```

`库内导出.py` 的 `do_export(unit, cfg, tables, dry_run)` 里，`unit` 只会是 `"标准投"` 或 `"简单投"`（见 `每日对账.py` 的导出步骤）；表名和 SQL 都在这个文件里，别放进 ini（`%` 会被 configparser 插值）。

## 4. 必须改的地方

### 4.1 硬阻塞 —— 不改就跑不起来

| # | 位置 | 写死了什么 | 怎么改 |
|---|---|---|---|
| 1 | `业务/自动对账.py` 的 `NEED_FILES` | `平台/<平台>/配置/聚光.ini` | 按 `[平台] product` 拼文件名 |
| 2 | `业务/项目配置.py` 的 `[凭证字段]` + `[凭证A..]` 校验 | 强制 cookie 后缀 / `login_proof` / 浏览器 `port+profile+curl` 四件套 | 改成「平台 ini 自己声明需要哪些凭证字段、要不要浏览器」；API Key 类平台既没有 cookie 也没有 profile |
| 3 | `监控内核/契约.py` 的平台表 SPEC | 列名 `fee_yuan / statistics_date / shop_name / fetched_at` | 要么让新平台适配层输出同名列（推荐），要么在这里改 SPEC |
| 4 | `平台/小红书/聚光/凭证刷新.py` | `mcc.xiaohongshu.com` 主机常量、sso 7 天假设 | 新适配层自己重写，别照抄这个文件 |
| 5 | `平台/小红书/聚光/凭证体检.py` | `PROBE` 探测地址 | 同上。注意它在 `业务/` 下，位置本身就不对 |

### 4.2 半阻塞 —— 「两路库内」的模型

数据模型是 **平台 − 标准投 − 简单投 = 差额**，每店固定 4 列：

| 位置 | 内容 | 影响 |
|---|---|---|
| `业务/每日对账.py` | 只导 `["标准投"] + (["简单投"] if has_simple)` | 第三路金额无处安放 |
| `监控内核/契约.py` | 固定 4 个校验任务，只有简单投 optional | 第三路不会被校验 |
| `监控内核/路径.py` | `STD_CSV` / `SIM_CSV` 两条写死路径 | 第三路没有路径常量 |
| `业务/写入日监控.py` | 每店 4 列（平台/标准投/简单投/差额），`CPR = 4` | 列语义变了要改看板 |
| `监控内核/判定.py` | `judge(plat, db, ...)` 只吃两个金额，`diff = plat - db` | 三方勾稽无法表达 |

只有一路金额时**不用改**：`连接配置.ini` 的 `[tables] simple` 留空，三处会明确跳过。
有第三路时：属于第 1 阶段改造（把「金额源」抽象成配置驱动的列表），不是本次清单范围。

### 4.3 不改也能跑，但会误导人

`排查.py`、`每日对账.py` 报错文案里的 `平台/<平台>/聚光/`、`启动取数浏览器.py` 的注释，都写着小红书/聚光的措辞。换平台时顺手改掉，否则排查时会对着错的路径找。

## 5. 改造步骤（按顺序，每步都要看到期望输出）

**1）先确认目标平台的数据能拿到**

在浏览器里手工抓一次 API，确认能拿到「日期 + 店铺 + 金额」。拿不到就别往下走 —— 后面的活全白做。

**2）建目录与配置**

```
平台/<site>/<product>/            4 个适配脚本
平台/<site>/配置/<product>.ini    [平台账号] [凭证字段] [凭证A..]（字段按新平台定）
```

**3）改 `[平台]` 两行**

`项目配置.ini` 的 `site` / `product`。改完 `python 项目配置.py` 必须能过 —— 这一步会把「目录不存在」「组织码不是数字」「分组名下没店」全拦住。

**4）写 `凭证刷新.py`**

新平台的登录态怎么拿（cookie / OAuth / API Key）完全由它决定。返回可用份数。

**5）写 `平台取数.py`**

按 §3.1 的列名产出 `日汇总.csv`。写完单独跑一遍，确认 `python -m 监控内核.契约` 通过。

**6）写 `库内导出.py`**

改 SQL 到新平台的库结构，但**输出列名保持不变**（`sub_account_id/total_cost` 等）。这一步能不改契约就尽量不改 —— 契约是护栏，改它等于拆护栏。

**7）跑一遍只读验收**

```bash
python 项目配置.py                  # 全部检查通过
python 写入日监控.py --selftest      # 表结构
python -m 监控内核.契约 --selftest   # 6 项
python -m 监控内核.契约              # 四张表真实数据
python -m 监控内核.自测_判定         # 75 项
python 排查.py --last                # 随便挑一天，看能不能出结论
```

**8）最后才碰真数据**

`python 每日对账.py --no-write` 跑一次（不加 `--no-write` 会写看板）。确认退出码 0/3/4 之一，再让计划任务接管。

## 7. 已知缺口

- `新建客户.py` 只生成「小红书/聚光」一套（`PLATFORM_DIR` / `PRODUCT` 写死）。换平台要手工建目录，或先改那个脚本。
- 适配层四个函数名没有断言，写错只报 `AttributeError`；想更稳可以写一个「接口自检」脚本，断言文件和函数都在。
- `账户取数.py` 和 `凭证体检.py` 不在任何调用链里，却含最硬的平台常量 —— 换平台时别以为它们会跟着换。
- 登录态提醒假设「sso cookie 7 天有效」。OAuth / API Key 平台要重写这段提醒（`监控内核/登录态.py` 与 `平台/.../凭证刷新.py` 的文案都在假设它）。

## 8. 踩过的坑

1. **别只改 ini 不改代码**：`[平台]` 改了但目录没建，路径会指向不存在的位置，报「找不到平台配置文件」——这是运气好的情况；运气不好时它读到默认值，拿小红书的口径去跑新平台。
2. **别在客户项目里改适配层**：改的是副本，`同步.py` 下次分发会报冲突，而且版本核对只提示不拦，每天照跑。
3. **`fetched_at` 别写「当天」**：取于统计日结束之前的值会被判「平台陈旧」，整天不报警 —— 这是正确行为，不是 bug。
4. **金额单位只除一次**：平台返回分 → 适配层除 100 写 CSV；库内 `cost` 本身是元，SQL 里不要再除。
5. **简单投没有就留空**，别填假表名：空表名拼出的 SQL 会报错，把「本来没有」变成「导出失败」。
